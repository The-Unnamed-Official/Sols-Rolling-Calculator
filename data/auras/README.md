# Aura directory sources

The local `/auras/` directory and individual aura pages are generated by
`node tools/build-aura-pages.cjs`. Refresh the wiki snapshot first with
`node tools/fetch-aura-wiki.cjs` when updating game information.
Directory-only wiki title artwork can be refreshed with
`node tools/fetch-directory-title-art.cjs` (requires `cheerio`, `postcss`, and
`postcss-selector-parser` in `test-results/wiki-tools/node_modules`, as used
by the existing wiki title build tool). The directory reuses the simulator's
shared stylesheets and default biome background. Links explicitly name
`index.html`. Hosted pages fetch the HTML fragments directly. File previews
and failed HTML requests use the shared `scripts/aura-layout-fragments.js`
fallback, so styles and controls still load.

Aura pages fetch their shared HTML through `scripts/aura-page-layout.js`.
Edit these partials once; the directory and all profiles use the changes on
their next load without rebuilding or editing any aura HTML files:

- `partials/header.html`: top bar, simulator version, and game build (currently
  Eon 1-29). The `data-version-id` also supplies the asset cache version and
  footer version; update it together with the visible simulator version.
- `partials/aura-header-controls.html`: Home and Settings controls.
- `partials/aura-body.html`: body classes, shell classes, and backdrop.
- `partials/aura-head.html`: shared styles, fonts, icons, and scripts, in
  dependency order. `{{assetPrefix}}` resolves to the site root and
  `{{appVersion}}` comes from the header.
- `partials/aura-footer.html`: shared footer and attribution.
- `partials/aura-profile-navigation.html`: All auras and Open simulator buttons.
- `partials/quality-preferences.html`: shared quality settings. Aura pages use
  the UI animation, roll/sigil animation, and aura styling controls.

The home page embeds `header.html`, `home-header-controls.html`, and
`quality-preferences.html` at build time. Run `node tools/build-aura-pages.cjs`
to update those home-page copies or regenerate aura content when the roster
or wiki snapshot changes. The build preserves the editable aura partials.
The aura loader revalidates fragments and resolves paths from its own script,
so both nested profile URLs and hosting under a project subdirectory work.
For file previews, run `node tools/build-aura-pages.cjs` after editing a partial
to refresh the single fallback bundle. Hosted pages read the HTML changes
directly without rebuilding profiles.
Run `node tools/check-aura-layout.cjs` to check that every generated page uses
the shared layout and that fragment asset paths and build metadata agree.
Profiles embed only their own title artwork in a small JSON block. The complete
title registries and filter controls load only on the directory. Structural CSS
and scripts load together; remote font imports do not delay page initialization.
Title animations pause when their cards are outside the nearby viewport.
Malformed wiki declarations are normalized by `scripts/wiki-title-repairs.js`.
Supplemental animations in `styles/wiki-title-repairs.css` are adapted from the
wiki's `MediaWiki:AuraKeyframes.css` and `MediaWiki:Common.css`, under the same
attribution and license as the existing title styles.

Aura page preferences use the simulator's existing local storage key.
The directory has four sort directions and
combined biome, exclusiveness, event, tier, and text filters. Each category
supports multiple selections, matching any selected value within that category.
Search, selections, sort order, page number, and scroll position are encoded in the
directory URL. Profile links carry that return URL, so All auras restores the exact
directory view. Plain directory links from Home and other navigation start fresh.
Settings → Quality Preferences includes a slider for 9–90 auras per page, with
18 as the default, snapping to increments of 3. The page size is saved across visits. Filters and sorting
operate on the entire roster. Only the current page's cards are visible; the title
artwork and fonts on the previous and next pages are prepared in an inert buffer.
Changing a filter or page size returns to the first matching page.
Rarity sorting follows the wiki's tier groups before sorting the odds within each
group, so Challenged effect-pool rarities do not mix with common roll rarities.
Event, unobtainable, and developer tiers retain their own filters and groups.
Every generated document paints a dark background immediately, before any
stylesheets or layout fragments load, and hides the shell until it is styled.
The backdrop follows a single selected biome; multiple selections restore the
default. Profiles use their native or required biome, including Rainy for
Poseidon. Historical versions use their archived biome when recorded. Background
assets come from the simulator's existing biome asset map. Glitch uses its
existing muted video; playback pauses for reduced motion and hidden pages.
Aura pages also expose Audio Settings for biome music, UI volume, UI sounds,
and master mute. Volumes use the simulator's audio storage key without replacing
its cutscene or obtain-sound preferences. Audio loads on interaction and pauses
when the page is hidden. The page-size slider shares the audio slider artwork.
Slider cards reserve label and value space so tracks remain aligned.

`wiki-reference.json` contains descriptions and obtainment information from
[Sol's RNG Wiki](https://sol-rng.fandom.com/wiki/Sol%27s_RNG_Wiki), retrieved
through its public MediaWiki API on October 3, 2026. The roster comes from
[Template:Auras](https://sol-rng.fandom.com/wiki/Template:Auras), supplemented
by simulator title references. Each record identifies its source article
and revision. Authors can be found in each article's revision history.

Wiki text is shared under [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/).
Descriptions have been converted from wiki markup to plain text and shortened
to at most 25 words. The page labels shortened text as an excerpt and links
to the full source. Adapted wiki text remains available under that license.
Missing in-game descriptions are identified rather than invented. All profiles
preserve the complete recorded descriptions, including changes
after the opening words, with Show More controls for long text. Those adapted
descriptions carry the same wiki attribution, source revision, and CC BY-SA
license.

`history.json` records the October 4, 2026 audit of all 485 aura articles, with
152 historical versions on 112 profiles. Every profile has a current preview.
Historical galleries, explicitly old
description tabs, and article revisions before documented reworks supply the
version records. Archived image revisions are resolved when uploads replaced
an existing filename. Missing historical details are identified in the page;
current rarity or descriptions are never substituted for unknown older facts.
Submission concepts, bugged previews, images of other auras, and changes only
to cutscenes or abilities do not create appearance-version tabs.
Sapphire : Peace has only an unreleased submission preview, which is labeled
as a concept. File names preserve case after the first character, as required
by MediaWiki: `CometInGame.gif` and `CometIngame.gif` are different uploads.
Images marked as awaiting an update are excluded when a current preview exists.
General gallery captions are not guessed into version groups. Historical tabs
use explicit infobox labels or images matched to their source revisions; an
unrecorded historical image is identified instead of repeating the current one.
Current profiles consistently show tier, type, and availability, plus event,
soundtrack, and creator information where recorded, alongside rarity and obtainment.
Recorded descriptions preserve supported wiki inline colors, outlines, bold text,
line breaks, and sigils. Rendering allows only text formatting, removes executable
HTML and CSS URLs, and uses the existing biome, aura, and item styles. Biome
mentions in obtainment, native odds, and location text use the same sigils.

Raw MediaWiki responses are cached under ignored `test-results/aura-history/`.
Omit `--refresh` to reuse the cache, or run `node tools/build-aura-history.cjs`
to rebuild the reviewed records without fetching. Ambiguous labels and the
documented Viridescent Memory predecessor are resolved in
`tools/aura-history-overrides.json`, with a reason for each mapping.
Each generated profile contains only its own version panels. The first image
starts downloading from the initial HTML at high priority. Remaining
media gets its `src` when the viewer preloads it after that first preview is ready.
All images, including historical versions, preload and decode
in the background. Smaller previews are used where available, with the original
image retried when a resized preview fails. The shared tab script
loads only on profiles and supports arrow keys, Home, and End. The browser
does not download the full history registry.
The viewer sits on the left on desktop and above the details on smaller screens.
Mutation navigation appears above the historical version tabs on related profiles.
Families come from the wiki's skin galleries and explicit mutation relationships.
Their links use the aura artwork, mark the active profile, and reserve measured
space for layered titles so names do not overlap the mutation labels.
The directory prepares the current page and one page on either side, including
their fonts and measured title frames, in an inert hidden grid. Buffers follow
the active filters, sort order and page size; their animations stay paused.
Existing title frames are reused when cards return to the visible page.
Additional wiki effects and fonts are shared with profiles too, including Faster
One for Layers and the generated text used by Abomination. Font imports load
separately from structural title effects so they do not block profile rendering.
Search, filters, sorting, page size and page number live in the directory URL.
Opening a card carries that URL and scroll position through its profile and
mutation links. Only its All auras button uses that return URL. Plain links from
Home, breadcrumbs and roll results open a fresh directory; no global filter
state is saved to local or session storage. The page-size setting remains a
shared user preference.
It shows one image at a time with image buttons and previous/next arrows. Image
transitions combine depth, fade, and a light sweep, respect reduced-motion
preferences, and handle rapid navigation without displaying a stale selection.

Playable soundtrack uploads are resolved by `tools/fetch-aura-soundtracks.cjs`
through the public MediaWiki API and saved in `soundtracks.json`. Rebuild history
and pages after refreshing audio. Each version uses its own recorded music files;
unresolved audio stays a wiki reference. Inline players have Play/Pause, seeking,
elapsed/duration labels and volume controls that expand on hover or keyboard
focus. Audio downloads on Play, leaving initial image downloads free of this
traffic. Playing a soundtrack pauses biome music; pausing it resumes biome music.
Master mute covers both, and changing a version stops its hidden soundtrack.

Cutscene and ability videos appear below the image viewer where a wiki section
records them. `tools/fetch-aura-showcases.cjs` resolves video metadata into
`showcases.json`; rebuild history and pages afterward. Wiki labels identify
individual recordings, including previous openings independently of aura reworks.
Historical panels use the videos from their source revision when available;
replaced uploads are resolved from the file history before that revision.
Leaked and concept recordings are excluded. Each disclosure loads its video only
when expanded, with custom play/pause, seek, expanding volume, playback speed,
fullscreen and picture-in-picture controls, plus links to the upload and article
revision. Collapsing it or changing aura versions pauses inline playback. The
floating player keeps the same media element while Home, the directory and other
profiles load in a same-origin navigation frame beneath it. The address bar and
Back/Forward history follow the displayed page; Return restores the source aura
and playback position. Videos opened in the navigation frame transfer their
playback state to the persistent player. Soundtracks and showcase videos pause
one another and biome music, and share master mute. Download controls and the
video save context menu are omitted; browser-playable public media is still
retrievable and this is not a DRM system.
Run `node tools/check-aura-showcases.cjs` to validate labels, source attribution,
placement, and loading behavior across the roster.
Run `node tools/check-aura-video-player.cjs` for navigation destinations, media
source validation, Home integration, and generated custom-player markup.

`catalogue.json`, `scripts/aura-routes.js`, `auras/index.html`, and the individual
`auras/<slug>/index.html` files are generated. Simulator mappings come from
the actual aura and event definitions in `scripts/main.js`. Numeric roll odds
sort from most common to rarest within their tier by default; crafted and other
special groups follow the regular roll tiers.
Scientific notation is preserved for display and parsed numerically for sorting:
THE RAREST AURA displays `1 in 16e+306`, with a denominator of `1.6e+307`.
Historical event odds fall back to the simulator registry when the wiki marks
the aura as unobtainable instead of publishing its original roll rarity.
